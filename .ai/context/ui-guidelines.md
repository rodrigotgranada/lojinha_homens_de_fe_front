# UI Guidelines

This document defines the official visual, compositional, and interface guidelines for the platform.

The goal is not only visual consistency.

The goal is to create:

* premium enterprise UX
* scalable visual systems
* cohesive interfaces
* predictable interaction patterns
* reusable visual foundations
* AI-friendly UI generation

The platform should feel modern, intentional, lightweight, and production-ready.

---

# Core UI Philosophy

The interface should feel inspired by:

* Linear
* Vercel
* Stripe
* Notion
* Raycast

The UI should prioritize:

* clarity
* simplicity
* hierarchy
* spacing consistency
* low visual noise
* smooth interactions
* responsive behavior

Avoid visual excess.

---

# Visual Identity Principles

The platform should feel:

* modern
* lightweight
* premium
* enterprise-grade
* scalable
* clean
* fast
* minimal

The interface should avoid unnecessary decoration.

---

# Layout Philosophy

Layouts should prioritize:

* readability
* breathing room
* predictable spacing
* responsive structure
* visual rhythm

Avoid crowded interfaces.

The UI should feel spacious without wasting screen real estate.

---

# Spacing System

Spacing consistency is mandatory.

Prefer spacing scales instead of arbitrary values.

Preferred spacing behavior:

* consistent padding
* consistent gaps
* predictable margins
* visual rhythm alignment

Avoid:

* random spacing
* inconsistent density
* visual compression
* uneven layouts

---

# Density Philosophy

Enterprise interfaces should balance:

* information density
* readability
* usability

The interface should never feel:

* empty
* oversized
* compressed
* cluttered

Density should adapt to context.

---

# Typography Philosophy

Typography should prioritize:

* readability
* hierarchy
* consistency
* responsive scaling

Typography should guide attention naturally.

Avoid:

* excessive font sizes
* inconsistent text hierarchy
* visual noise
* oversized headings

---

# Typography Hierarchy

Preferred hierarchy:

* clear page title
* visible section title
* supportive descriptions
* subtle metadata
* readable body text

The interface should communicate importance visually.

---

# Card Philosophy

Cards should behave as:

* isolated information containers
* modular UI units
* reusable layout primitives

Cards should prioritize:

* breathing room
* predictable spacing
* subtle hierarchy
* clean structure

Avoid:

* excessive borders
* heavy shadows
* visual overload

---

# Table Philosophy

Tables should prioritize:

* readability
* scanability
* responsive behavior
* predictable actions
* information hierarchy

Tables must support:

* loading states
* empty states
* responsive overflow
* row actions
* keyboard accessibility

Avoid visually dense tables without spacing.

---

# Form Philosophy

Forms should feel:

* lightweight
* guided
* responsive
* accessible
* low friction

Forms must prioritize:

* spacing clarity
* validation visibility
* async feedback
* keyboard usability
* mobile usability

Avoid overwhelming forms.

---

# Input Philosophy

Inputs should prioritize:

* clear focus states
* accessible labels
* predictable sizing
* validation visibility

Inputs should feel responsive and intentional.

Avoid:

* tiny click areas
* unclear states
* inconsistent heights

---

# Modal Philosophy

Modals should feel:

* focused
* lightweight
* contextual
* interruptive only when necessary

Modals should avoid:

* oversized layouts
* excessive nesting
* giant forms
* scroll chaos

Prefer drawers for large workflows.

---

# Drawer Philosophy

Drawers should prioritize:

* workflow continuity
* contextual editing
* responsive layouts
* smooth interaction

Drawers should feel integrated into the application flow.

---

# Tabs Philosophy

Tabs should organize related content clearly.

Tabs should prioritize:

* discoverability
* navigation clarity
* low visual noise

Avoid excessive tab nesting.

---

# Scroll Philosophy

Scrolling should feel:

* smooth
* intentional
* visually integrated

Scrollable areas must:

* preserve context
* avoid layout jumps
* maintain usability

Avoid hidden scroll behavior.

---

# Async UI Philosophy

Async states are part of the interface design.

The UI must support:

* skeletons
* loading indicators
* optimistic transitions
* retry states
* graceful empty states

Avoid blank containers during loading.

---

# Skeleton Philosophy

Skeletons should:

* preserve layout structure
* reduce layout shift
* communicate progress
* feel lightweight

Skeletons should approximate final layout shape.

Avoid random placeholder blocks.

---

# Empty State Philosophy

Empty states should feel intentional.

Empty states should:

* explain context
* guide next actions
* preserve layout quality

Avoid dead-end interfaces.

---

# Error State Philosophy

Error states should feel graceful.

Requirements:

* clear messaging
* retry actions
* isolated failures
* non-destructive UX

Avoid raw backend errors.

---

# Responsive Philosophy

Mobile-first is mandatory.

Interfaces should:

* scale progressively
* preserve usability
* adapt spacing
* support touch interactions
* preserve hierarchy

Desktop should enhance the mobile experience.

---

# Mobile UX Philosophy

Mobile interfaces must prioritize:

* touch ergonomics
* readable spacing
* proper scroll behavior
* keyboard-safe layouts
* low friction navigation

Avoid desktop layouts compressed into mobile.

---

# Accessibility Philosophy

Accessibility is mandatory.

All interfaces must support:

* keyboard navigation
* visible focus states
* semantic HTML
* screen readers
* reduced motion preferences

Accessibility should feel native to the system.

---

# Motion Philosophy

Animations should feel:

* subtle
* smooth
* intentional
* performance-friendly

Motion should support comprehension rather than decoration.

Avoid excessive animation.

---

# Hover Philosophy

Hover interactions should:

* communicate affordance
* remain subtle
* avoid aggressive movement

Hover should enhance clarity, not distract.

---

# Color Philosophy

Colors should prioritize:

* readability
* hierarchy
* semantic meaning
* accessibility

Avoid:

* excessive saturation
* noisy interfaces
* inconsistent semantic colors

The UI should feel calm and controlled.

---

# Dark Mode Philosophy

Dark mode should feel:

* balanced
* readable
* low-glare
* visually cohesive

Avoid extreme contrast.

Dark mode should preserve hierarchy and usability.

---

# Border Radius Philosophy

Radius should remain consistent.

The interface should feel:

* modern
* soft
* structured

Avoid inconsistent radius usage.

---

# Shadow Philosophy

Shadows should remain subtle.

Shadows should communicate:

* elevation
* layering
* focus

Avoid heavy shadows or visual clutter.

---

# Loading Feedback Philosophy

Loading feedback should always exist.

Users should never wonder:

* if the UI is frozen
* if an action succeeded
* if content is loading

Feedback should feel immediate and predictable.

---

# Enterprise UX Philosophy

Enterprise UX must prioritize:

* scalability
* predictability
* low friction
* fast workflows
* information clarity

The interface should support professional usage patterns.

---

# Design System Philosophy

The design system should behave as:

* a reusable UI platform
* a scalable visual language
* a predictable UX foundation

Consistency is more important than isolated visual experimentation.

---

# AI-Friendly UI Philosophy

The UI system must optimize:

* semantic consistency
* reusable patterns
* predictable composition
* scalable abstractions

The interface should remain easy to understand and extend.

---

# Forbidden UI Patterns

Avoid:

* crowded layouts
* oversized modals
* excessive visual effects
* inconsistent spacing
* arbitrary sizing
* visual noise
* hidden actions
* ambiguous interactions
* layout shifts
* abrupt async transitions

---

# Preferred UI Characteristics

Prefer interfaces that feel:

* cohesive
* lightweight
* premium
* accessible
* scalable
* responsive
* predictable
* intentional

---

# Final UI Goal

The final interface should behave as:

* a premium enterprise product
* a scalable design system
* a reusable frontend platform
* a production-grade SaaS experience

Every screen should feel cohesive with the platform ecosystem.
